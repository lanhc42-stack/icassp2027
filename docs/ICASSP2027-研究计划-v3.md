## 一、摘要式定位

我们在直播 ASR 生产环境中观察到:当背景音乐含人声时,ASR 的行为是**双峰且不稳定的**——有时把歌词一并转录,有时只转录主播的说话声。

本工作把这一现象形式化为**无条件的源选择歧义**:两个都合法的语音源同时存在、且不给模型任何条件时,它如何选择?

我们在**三个模型族上做 2×2 解耦对照**——隐式 LM 解码器(Whisper)、显式 LLM 解码器且未经歌曲训练(Granite-speech)、显式 LLM 解码器且经歌曲训练(Qwen3-ASR)——从而把"解码器类型"与"是否训练过转歌词"两个变量分开;并刻画选择的相变行为、定位决策发生的位置、给出轻量缓解方法。

**核心问题**:更强的语言先验,是加剧还是缓解源选择歧义?

## 二、问题背景

### 2.1 现象描述

直播场景中主播说话与背景音乐(BGM)常并存,而 BGM 往往含人声。此时 ASR 输出呈三种模式:

1. 仅转录主播说话声(期望行为)
2. 说话声与歌词混合转录(污染)
3. 主要转录歌词,主播说话被压制(严重污染)

三者切换缺乏明显规律,同一路流在相近条件下可能给出不同结果。

### 2.2 为什么这是个真问题

**危害是隐蔽的。** 混入的歌词在语法上流畅通顺,下游消费者(意图分类、内容理解、推荐特征、审核)无法从文本本身判断是否被污染。这与"ASR 出错导致文本不通顺"性质完全不同——常规错误可被下游语言模型部分吸收,歌词污染则被当作真实内容处理。

**影响是级联的。** 内容理解链路以 ASR 为共享上游,一次污染同时传播到所有下游任务。

**趋势上会更严重(如果 H-LM 成立)。** 业界正从隐式 LM 解码器转向显式 LLM 解码器。若更强的语言先验加剧了歧义,这个问题会随架构演进而放大,而非缓解。

### 簇四:编码器保留背景声信息(H1 核心证据)

| 工作 | 关键发现 | 链接 |
|---|---|---|
| **Whisper-AT**(Interspeech 2023) | Whisper 虽对背景声鲁棒,但其音频表示**并非噪声不变**,而是与非语音声高度相关,**说明 Whisper 是"以噪声类型为条件"识别语音的**;冻结骨干 + 轻量标注头,<1% 额外算力即可输出音频事件 | https://arxiv.org/abs/2307.03183 · https://github.com/YuanGongND/whisper-at |

**"以噪声类型为条件识别语音"意味着模型内部本就存在关于背景类型的表示,并会调制识别行为。** 我们的假设正是:当背景被判定为"含人声的音乐"时,该条件化机制变得不稳定。

### 簇五:隐式 vs 显式 LM 解码器的对照研究(实验范式模板)

| 工作 | 内容 | 链接 |
|---|---|---|
| Do LLM Decoders Listen Fairly? | 用 Whisper small→medium→large-v3(隐式 LM 缩放)、Qwen3 0.6B→1.7B(显式 LLM)、Granite 2B→8B 做受控对比,研究 LM 先验如何塑造 ASR 偏见 | https://arxiv.org/abs/2604.21276 |

**这篇给了我们两样东西**:一个已被验证可发表的实验设计范式,以及一个可对齐的模型选型。我们把同一范式用于源选择歧义。

### 簇六:多源竞争下的选择——空白所在

目标说话人 ASR(TS-ASR)、多说话人 ASR 存在"转录哪个源"的问题,但**目标由说话人 embedding 或注册语音显式指定**。

**没有工作研究:两个合法语音源同时存在、且不给任何条件时,模型自身如何选择,以及为何不稳定。**

### 3.7 定位总结

| 研究方向 | 转写目标 |
|---|---|
| Whisper 幻觉 | 无目标(输入无语音) |
| 歌词转写 ALT | 歌词(伴奏是噪声) |
| 标准 ASR | 说话声(音乐是噪声) |
| 目标说话人 ASR | 由 embedding **显式指定** |
| **本工作** | **两个合法语音源,无任何条件,模型自选** |

**一句话:这不是鲁棒性问题,是无条件的源选择歧义问题。**

### 3.8 与最接近一篇的承接

*Beyond Transcription* 已证明 Whisper 把"语音 vs 非语音"编码为线性可分方向。我们的切入点是它未回答的问题:

> **唱歌既是语音也是音乐。它在这个线性方向上的投影落在哪一侧?该投影的不确定性,是否就是行为不稳定的来源?**

## 四、研究问题与假设

**RQ1** 源选择是渐变还是相变?由哪些声学 / 语言因素驱动?
**RQ2** 决策发生在编码器还是解码器?
**RQ3** 更强的语言先验(显式 LLM 解码器)加剧还是缓解歧义?
**RQ4** 能否定位到具体的层、方向或注意力头?
**RQ5** 能否用轻量干预稳定该行为?

### 待检验假设

| | 假设 | 先验依据 |
|---|---|---|
| **H1** | 编码器保留两源信息,选择发生在解码器 | Whisper-AT 表明编码器保留并高度相关于背景声;Cascade Equivalence 报告声学信息全程保留。**新增:内部 encoder+CTC 模型提供行为层面的直接检验——无解码器可供选择,若它照样泄漏,H1 即成立(§6.7 一)** |
| **H2** | 存在由相对能量(SNR)驱动的相变点,而非平滑过渡 | 生产观察到的是双峰而非渐变 |
| **H3** | "歌唱性"本身(而非内容或说话人)是开关的主要输入 | 用 §5.3 朗读对照直接检验 |
| **H4** | 语言一致性是隐式开关(中文主播 + 中文歌 vs + 英文歌行为不同) | Whisper 多任务训练含显式语言 ID;若成立说明选择发生在语言判定之后 |
| **H-LM** | **歌词泄漏随解码期语言先验强度单调上升**(无 → 隐式 → 显式) | LLM 解码器更擅长把模糊声学证据补全为流畅文本。**v4 改为三级剂量—反应形式**:内部 CTC 模型提供零点,单调趋势比两点差值更有说服力(§6.1) |
| **H5** | 存在可因果干预的线性方向或组件 | *Beyond Transcription* 已证明 speech/non-speech 方向线性可分 |

**H-LM 是核心假设,也是论文最有分量的一条**——它把研究对象从"一个老模型的缺陷"提升为"一个架构趋势的副作用"。v4 借内部 CTC 模型把它做成**三级阶梯**,是本版对论证强度的最大提升。

## 五、数据构造(关键路径)

### 5.1 设计原则

必须能**独立获知两个源各自的 ground truth**,才能精确度量歌词泄漏。因此以受控人工混合承载主结论,生产数据作动机与验证。

### 5.2 数据来源

| 角色 | 来源 | 说明与链接 |
|---|---|---|
| 说话声(目标,中文) | 生产环境抽取的干净主播语音段 | 需走脱敏流程 |
| 说话声(目标,英文) | **LibriSpeech** test-clean | 开放下载**无需审批**,朗读英语,规避审批风险 |
| 中文歌声 + 伴奏 | **MIR-1K** | 1000 片段(每段 **4–13 s**,共 133 分钟,19 位演唱者),伴奏与歌声**分录左右声道**,含音高轮廓、清音帧、歌词、人声/非人声段标注,**以及同一演唱者朗读歌词的录音** https://zenodo.org/records/3532216 |
| **英文歌声 + 朗读对照** | **NHSS** | **100 首英文流行歌、10 位演唱者(5男5女)、7 小时**;同一演唱者的**演唱与朗读歌词平行录音**,含句级与词级标注。**这是 MIR-1K 的英文等价物,使 C4 对照可在英文臂复现** https://hltnus.github.io/NHSSDatabase/ · https://arxiv.org/abs/2012.00337 |
| 英文伴奏 | **MUSDB18-HQ** | 150 首整轨,提供 mixture/vocals/drums/bass/other 分轨,44.1 kHz 无损;**本版仅取其伴奏分轨**为英文臂提供 C1/C3 的器乐 https://zenodo.org/records/3338373 · 工具 https://github.com/sigsep/sigsep-mus-db |
| 真实验证集 | 生产环境真实带 BGM 片段 | 见 §9 合规路径 |

备选:**NUS-48E**(48 首、12 人的演唱+朗读平行语料)可作 NHSS 的补充或备份。

### 5.2a 两条数据臂(v4 新增,由 §6.3 决定)

Granite 不支持中文 ASR,2×2 解耦必须在英文臂进行。因此数据分为两臂,**各自独立完成 C1–C4**:

| | **英文臂** | **中文臂** |
|---|---|---|
| 目标说话声 | LibriSpeech test-clean | 生产脱敏主播语音 |
| 歌声 | NHSS(演唱) | MIR-1K(演唱) |
| **C4 朗读对照** | NHSS(同人朗读) | MIR-1K(同人朗读) |
| 伴奏 | MUSDB18-HQ 分轨 | MIR-1K 伴奏声道 |
| 可跑模型 | **三族全部(7 个模型)** | Whisper + Qwen3-ASR + 生产模型 |
| 承载 | **Fig 2 解耦对照** | Fig 1、Fig 3、H3/H4、生产验证 |

**两臂都有同人朗读对照,是这套设计意外的好处**:C2/C4 的"歌唱性"效应可在两个语种上各测一次,**跨语种复现比单语种结果强得多**,几乎不增加成本。

**关键路径修正**:v3 §11 认为 MUSDB18 可延后——**该判断作废**。但风险比 v3 更低,因为:

- 英文臂的说话声用 **LibriSpeech,无需审批**;
- **NHSS 公开发布**,不走 Zenodo 限制性审批;
- MUSDB18-HQ 现在只用于提供器乐伴奏,**若审批受阻,可用任意无人声器乐替代**(C1/C3 只要求"是音乐",不要求与歌声同源)。

即英文臂的关键路径依赖已从"两个需审批数据集"降为"NHSS 一个公开数据集"。

### 5.3 MIR-1K 提供的关键对照

**MIR-1K 还提供了由同一位演唱者朗读同样歌词的语音录音。**

这给出一个近乎理想的控制变量设计:**内容相同、说话人相同,唯一差异是"唱"还是"说"**。

| 条件 | 干扰源 | 检验目标 |
|---|---|---|
| C1 | 纯器乐伴奏(无人声) | 基线,应仅转录主播 |
| C2 | 纯歌声(无伴奏) | 纯人声竞争 |
| C3 | 完整歌曲(歌声 + 伴奏) | 生产场景 |
| **C4** | **同一人朗读的同样歌词** | **分离"歌唱性"这一变量** |

**C2 与 C4 的对比是本工作最干净的实验**:若泄漏率显著不同,说明韵律层面的"歌唱性"本身是开关输入,而非内容或说话人差异所致(直接检验 H3)。该对照由 MIR-1K 白送,应优先做。

### 5.4 混合协议

- **SNR 扫描**:目标语音相对干扰源,−10 dB 至 +20 dB,步长 2.5 dB;**范围由生产分布的 5–95 分位校准**(见 §9)
- **语种组合**:中文臂 中—中 / 中—器乐;英文臂 英—英 / 英—器乐;跨语种 中—英(覆盖 H4)
- **片段长度:4–13 s**。v3 原定 10–30 s **与 MIR-1K 实际不符**(该库每段 4–13 s),拼接多段又会引入切换点、制造新混淆。**改为放宽下限,论文中报告长度分布。** NHSS 按句级标注切分后落在同一量级。
- **采样率**:统一 16 kHz 单声道
- 随机种子固定;混合脚本与配置随论文开源

### 5.5 规模建议

优先保证条件覆盖完整性。每臂粗估:4 条件 × 13 个 SNR 点 × 2 语种组合 × 每格 50 片段 ≈ **5200 条/臂**,两臂约 **10400 条**。

推理量:中文臂 5200 × 6 模型(Whisper×3 + Qwen3-ASR×2 + 生产)+ 英文臂 5200 × 7 模型(再加 Granite×2)≈ **6.8 万次推理**,片段 4–13 s。**Granite-8b 是最重的一档**,若算力紧张按 §6.5 先砍它。

**探针的说话人划分需注意**:MIR-1K 仅 19 位演唱者、NHSS 仅 10 位。做说话人无关划分时样本偏少,建议 **leave-one-singer-out 或报告 per-singer 方差**,不要只给单一准确率。

## 六、模型矩阵

**v4 核心变化:从"双线对比"改为 2×2 解耦设计,加入 Granite-speech。**

### 6.0 为什么必须加第三族

v3 把 Whisper↔Qwen3-ASR 的差异归因于**隐式 vs 显式 LM 解码器**。但两者之间同时变化的还有第二个变量:**Qwen3-ASR 被显式训练用于歌曲转写,Whisper 没有**(见 §6.2 二)。

两个变量捆在一起,H-LM 就无法证成:若 Qwen3-ASR 泄漏更多,审稿人会问"这是显式 LM 先验的副作用,还是它本来就被训练成要转歌词?"——而这正是全文最有分量的那条结论。

**Granite-speech 提供缺失的第三格:显式 LLM 解码器,但未针对歌曲训练。**

### 6.1 语言先验强度的三级阶梯 × 歌曲训练

内部的 **encoder + CTC 模型(whisper_ctc_offline,§6.7)** 提供了阶梯的**零点**:CTC 逐帧条件独立,**没有自回归解码器,没有解码期语言先验**。加上它之后,H-LM 从"两级对比"升级为**三级剂量—反应关系**:

| 语言先验强度 | 模型 | 解码器 |
|---|---|---|
| **无(零点)** | **whisper_ctc_offline** | 无解码器,greedy CTC |
| **隐式** | Whisper small/medium/large-v3 | AED 解码器,从头训练 |
| **显式** | Granite-speech 2b/8b · Qwen3-ASR 0.6B/1.7B | 预训练 LLM 解码器 |

**单调趋势远比两点差值有说服力。** H-LM 若成立,泄漏率应沿阶梯单调上升;若三级之间没有系统差异,则"泄漏源于目标定义歧义而非语言先验"这一更强结论直接成立。

第二维仍为**是否针对歌曲训练**,用于排除混淆:

| | **未针对歌曲训练** | **针对歌曲训练** |
|---|---|---|
| **无 LM 先验** | **whisper_ctc_offline** | —— |
| **隐式 LM** | **Whisper** small/medium/large-v3 | *(空,见下)* |
| **显式 LLM** | **Granite-speech** 3.3 2b/8b | **Qwen3-ASR** 0.6B/1.7B |

三条正交对照:

- **CTC ↔ Whisper** = 有无自回归 LM 的效应(**架构最接近的一对**,见 §6.7)
- **Whisper ↔ Granite** = 隐式 vs 显式先验的效应(歌曲训练固定为"无")
- **Granite ↔ Qwen3-ASR** = 歌曲训练的效应(先验类型固定为"显式")

"针对歌曲训练"一行仍只有一格有模型,**因此不估计交互项,论文中要明说**。若时间允许可用簇二的歌词微调 Whisper(https://arxiv.org/abs/2506.02339)补齐。加分项,不进最小可发版本。

### 6.2 完整模型矩阵

| 模型族 | 解码器 | 歌曲训练 | 规模档 | ASR 语种 | 编码器输出帧率 |
|---|---|---|---|---|---|

|---|---|---|
| Whisper large-v3 | 1.55B | 隐式 LM / 无歌曲训练 |

**band B —— 编码器预算匹配,承载"有无自回归 LM"对照(最干净的一对):**

| 模型 | 编码器 | 解码器 | 总参数 |
|---|---|---|---|

### 6.6 Qwen3-ASR 的三项特性

**一、Mel 前端与 Whisper 一致(适用范围已收窄)**
16 kHz、128 mel bins、n_fft=400、hop_length=160、Hann 窗、Slaney mel scale、0–8 kHz——与 Whisper 逐项相同。

**但不要把这一点推得太远。** 三族的编码器输出帧率分别是 Whisper 50 Hz、Qwen3-ASR 12.5 Hz、Granite 10 Hz,**最大差 5 倍**;Granite 更是 conformer + 自有前端,与前两者不同源。因此:

- **Fig 1 / Fig 2(只看输出文本)**:mel 一致的论点成立,但只覆盖 Whisper↔Qwen3-ASR 这一对。
- **Fig 3 逐层探针**:三族"第 k 层"覆盖的时间跨度不同,**逐层曲线不可直接叠加**。需按相对深度(layer/total)归一化,并在时间轴对齐后再比。
- v3 原文"无需'输入不可比'的免责声明"一句**已删除**——加入 Granite 后不再成立。

**待确认**:mel 参数逐项相同这一条,应直接 diff 两边特征提取代码确认(约 20 分钟)。技术报告只写了 128-dim Fbank,而 Fbank / log-mel、Slaney / HTK scale 的差别会影响这段论证。

**二、官方将"歌曲识别"作为卖点(= 2×2 的"歌曲训练"维度)**
Qwen3-ASR 明确支持多语种 speech / music / song 识别,即**被显式训练成"歌也要转"**。技术报告显示其在带 BGM 整曲转写上明显强于 Whisper-large-v3(EntireSongs-zh 13.91,Whisper 因表现过差标记为 N/A)。

**这正是 §6.1 中"歌曲训练"那一维的操作化定义**,也是必须引入 Granite 才能与解码器类型解耦的原因。

**三、附带 ForcedAligner**
Qwen3-ForcedAligner-0.6B 支持 5 分钟内任意单元的时间戳预测,覆盖 11 种语言。可用于**精确定位泄漏发生在片段的哪一时刻**,为 Fig 1 增加时间维度。

### 6.7 内部 encoder+CTC 模型:阶梯的零点

代码位置:`hyper_boot` 仓库 **`feat/whisper-ctc-offline`** 分支,`models/triton/whisper_ctc_offline/`
(master 上该目录只有空壳,模型定义在分支上)

**架构**(读自 `build/models/pytorch_model_ctc_ds6.py`):

| 项 | 值 | 与 Whisper large-v3 编码器对比 |
|---|---|---|
| n_mels | 128 | **相同** |
| hidden_size | 1280 | **相同** |
| num_layers | 32 | **相同** |
| num_heads | 20 | **相同** |
| 位置编码 | 正弦(固定,非学习) | **相同** |
| block 结构 | pre-LN,GELU FFN | **相同** |
| vocab | 51866(Whisper 多语种词表) | **相同** |
| **降采样** | **DS6(conv stride 2 × 3)→ ≈16.7 Hz** | **不同**(Whisper 为 DS2 → 50 Hz) |
| **解码器** | **无**,`Linear(1280→51866)` CTC 头 | **不同**(Whisper 有 AED 解码器) |

checkpoint:`whisper_ctc_sixty_turbo_20260610_recode_punc/model.pt.avg10`(内部训练,含标点重建)。

**关键性质:确为 greedy CTC,无 LM 融合。** `argmax` 直接固化在导出的 ONNX 图里(`yseq = log_probs.argmax(-1)`),后处理只做 CTC 去重合并与强制对齐(`blank_id=50256`),**无 beam search、无 shallow fusion**。这是把它当作"零语言先验"参照的前提,已核实。

**三项收益**

**一、直接检验 H1,且不依赖探针。**
H1 说"编码器保留两源信息,选择发生在解码器"。CTC 是对编码器输出的逐帧线性读出,**没有解码器可供"选择"**。因此:

- CTC **同时**转出说话与歌词(高泄漏)→ 编码器确实两源都保留,抑制只能是解码器行为 → **H1 成立,行为层面直接证实**
- CTC **也**压制歌词 → 选择已发生在编码器 → **H1 被否**,结论更强(见 §11)

**这是一个比 Fig 3 更便宜、更易读的 H1 检验**,且两者互为交叉验证。在 36 天的排期下,这一点价值很高。

**二、自带时间戳。** 后处理已实现 CTC 强制对齐,**§6.6 三想用 ForcedAligner 做的"泄漏发生在哪一刻",这里免费得到**。

**三、支持中文,可进中文臂。** 用的是 Whisper 多语种词表且带语言 token 检测,与 Granite 不同,**中文臂也能跑**,可与 Whisper/Qwen3-ASR 直接对照。

**两条必须写进论文的限制**

1. **不是"零语言先验",而是"零解码期自回归先验"。** 32 层编码器以文本为目标训练,必然吸收了语言规律性(checkpoint 还含标点重建)。措辞要精确,否则会被审稿人抓。
2. **内部模型不可复现。** 审稿人无法验证。因此**沿用 §9.3 的隔离原则:主结论必须由公开模型承载,CTC 模型只做加强**。建议补一个**公开的 encoder+CTC 模型**(如 NeMo Conformer-CTC 或 wav2vec2-CTC;内部 zoo 里的 `zipformer_asr`、`parakeet_tdt_0.6b_v3` 可作选型参考)把阶梯零点公开化,内部模型则提供"架构与 Whisper 对齐"的那一份干净对照。

| **双峰系数** | 同配置内泄漏率分布的双峰性,量化"不稳定"本身 |
| 探针准确率 / AUC | 逐层报告 |
| 泄漏时间定位误差 | 用 ForcedAligner,可选 |

## 九、生产数据的使用与合规路径

**定位:生产数据提供动机与验证,不承载主结论。**

三个理由:缺乏两源 ground truth;审稿人无法复现;审批周期不可控。

### 9.1 四个不可替代的用途

**一、一个学术组写不出的数字**
> "在 N 小时真实直播流量中,X% 的含 BGM 片段出现歌词泄漏。"

放进 introduction,把"我们观察到一个现象"变成"这是一个有规模的生产问题"。**只需统计量,不需公开音频,是最高性价比的用途。**

**二、校准合成实验的参数范围**
先从生产数据测出人声 / BGM 能量比的实际分布,据此设定 SNR 扫描范围。论文中可写"扫描范围覆盖生产分布的 5–95 分位",而非拍脑袋定值。**审稿人会注意到这个细节。**

**三、纵向一致性:直接量化"不稳定"**
同一主播、同一 BGM、不同时间点的行为是否一致?合成数据只能测样本间方差,**生产数据能测同一配置在时间上的重复不一致性**——这才是我们最初观察到的现象本体。

**四、极端案例:主播跟唱**
主播跟着 BGM 一起唱时,两个"源"是同一个人、内容相同、都在唱。这是源选择的极限测试,**合成数据无论如何构造不出来**。作为 discussion 中的 case study,并可反向验证 H3。

### 9.2 合规路径(按难度排序)

| 内容 | 难度 | 建议 |
|---|---|---|
| 统计量(泄漏率、能量比分布) | 低 | **争取,主要目标** |
| 匿名化转写片段样例 | 中 | 争取 |
| 音频样本 | 高 | 不强求 |
| 数据集公开发布 | 极高 | 不考虑 |

论文中平台匿名化为 "a large-scale production livestreaming platform",工业界论文的标准做法。

### 9.3 风险隔离

- 合成数据的申请与构建**照常进行,不等待审批**
- 生产数据分析作为**并行支线**,拿到即加入,拿不到即砍掉
- **每一个主结论都必须只依赖合成数据**
- 若第 4 周仍未获批,直接放弃该部分,不为其推迟投稿

## 十二、为什么值得做

**一、无论结果如何都能成篇。** 相变存在 → 定位离散开关;不存在 → 连续加权模型。探针支持 H1 → 解码器选择;不支持 → 编码器丢弃。H-LM 成立 → 趋势警示;不成立 → 训练配方指引。所有分支都有清晰叙事。

**二、地基已由前人打好。** 层级功能分工、探针方法学、声学信息保留、speech/non-speech 线性方向、隐式 vs 显式 LM 对照范式——均不必重做。

**三、2×2 解耦挡住了最致命的两条质疑。** 纳入 Qwen3-ASR 后,"这只是老模型的历史包袱"不再成立;再纳入 Granite 后,"泄漏只是因为它被训练过转歌词"也不再成立——**这两条质疑各由一个正交对照挡住,是 v4 相对 v3 的实质增益**。

**四、数据条件优越。** MIR-1K 的"同一人朗读同样歌词"对照可干净分离"歌唱性"变量,零额外标注成本。

**五、有直接业务价值。** 歌词污染传播到所有下游任务,且因转写流畅而不可察觉。

**六、可能白捡一个能力。** 若发现模型内部隐式做"唱歌 vs 说话"判别,该表示可直接用于音乐检测——恰是我们已有的业务需求。参照 Whisper-AT,冻结骨干加轻量头即可,额外算力 <1%。
