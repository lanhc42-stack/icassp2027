# Pilot 09 — 对照实验:那个"起始承诺"是**解码器造出来的**

pilot 08 在 Whisper 上定位到"起始 2 秒累积承诺 + 沿层固化"。
本次在**没有解码器**的 whisper_ctc_offline 上跑**完全相同**的实验(同曲目、同语音、同 SNR、同窗口)。
若承诺来自自回归解码器,无解码器模型就不该有它。

## 〇、先决条件:PyTorch 复现与部署一致

部署的是 TensorRT 引擎,无法插 hook,因此用分支里的 `pytorch_model_ctc_ds6.py`
加载同一份 checkpoint。前端严格对齐 DALI(16k / n_fft 400 / hop 160 / 128 mel /
`log10 → max(x, max−8) → (x+4)/4`),12 s bucket → 1200 mel 帧 → **200 编码器帧(16.7 Hz)**。

同一条 LibriSpeech 上的对照:

```

```

22 词中 20 词完全一致,差异来自 TRT/PyTorch 的 fp16 数值。**权重同源,patching 自洽。**

## 三、与 Whisper 的正面对比(本文的核心图)

一个 2 秒窗占 10 秒片段的 **20%**,所以"局部无承诺"的零假设预测:
**patch 任一窗 ≈ 消除 20% 的泄漏**,且各窗相当。

在第 0 层上,泄漏率的相对下降幅度:

| | 起始窗(0–2 s) | 其余四窗平均 | **起始优势** |
|---|---|---|---|
| **Whisper**(有解码器) | **88.4%** | 41.6% | **+46.8 个百分点** |
| **CTC**(无解码器) | 45.6% | 36.7% | **+8.9 个百分点** |

**Whisper 的起始优势是 CTC 的 5 倍以上。**

深度维度同样只在 Whisper 上存在:

| | L00 → L20 的 w0 残余泄漏 |
|---|---|
| **Whisper** | 0.095 → 0.444(**单调固化,跨度 0.35**) |
| **CTC** | 0.404 → 0.402(**基本持平**;L28 0.313,L31 0.634,无单调趋势) |

## 四、结论

> **"在起始 2 秒内形成、并沿层固化的全局源选择承诺",是自回归解码器的产物。
> 去掉解码器,源选择退化为逐帧的局部判定——每一段音频各自决定转写什么,
> 开头不再决定全局。**

这把 H-LM′ 从**相关**升级为**对照结论**:

- pilot 04 只能说"先验越强、泄漏越少"(三个模型,训练数据全不同,属关联);
- pilot 09 在**同一实验、同一素材**下证明:**承诺机制本身随解码器的有无而出现/消失**。

同时解释了 pilot 04 的阶梯为何单调:先验越强 → 早期承诺越稳固 → 越不容易被歌词翻盘。
也解释了 pilot 03 的双峰:承诺是全局二选一,所以结果两极;
而 CTC 逐帧独立,理应双峰性更弱——**这是一个可立即验证的预测**(见下)。

**注意:这与我事先的猜测相反。** 我原本预期"无解码器模型的承诺更容易被推翻",
实际是**它根本没有承诺**。方向猜错了,但机制假说被更强地支持了。

## 五、局限

1. Whisper 与 CTC 的 baseline 不同(0.822 vs 0.742),故比较用的是**相对下降幅度**,不是绝对值。
2. 两模型编码器帧率不同(50 Hz vs 16.7 Hz),2 秒窗对应帧数不同(100 vs 33)。
   窗口按**时间**对齐而非帧数对齐,这是正确的选择,但意味着 CTC 每次替换的向量数更少。
   **应补一个对照**:在 Whisper 上按"相同帧数比例"再跑一次,排除这一因素。
3. CTC 的 L31 行整体偏弱(0.62–0.67),原因未查明。
4. donor 为 +10 dB 同段混音,非干净语音。
