接口 `POST /v1/transcribe`,入参 `{"audio": <base64 wav>}`,返回 `{text, words:[{word,start,end}], language}`——

## 主结果:阶梯单调,但方向与 H-LM 完全相反

**歌词泄漏率**(C2_vocals,50 首 × 5 语音 × 3 SNR):

| 模型 | 解码期先验 | −10 | −5 | 0 |
|---|---|---|---|---|
| whisper_ctc_offline | **无** | **0.511** | **0.215** | 0.022 |
| Whisper large-v3 | **隐式** | 0.378 | 0.091 | 0.000 |
| Qwen3-ASR 1.7B | **显式 + 歌曲训练** | **0.244** | **0.054** | 0.004 |

**目标语音召回率**(还剩多少说话内容):

| 模型 | −10 | −5 | 0 |
|---|---|---|---|
| whisper_ctc_offline | 0.204 | 0.492 | 0.711 |
| Whisper large-v3 | 0.372 | 0.715 | 0.907 |
| Qwen3-ASR 1.7B | **0.516** | **0.795** | 0.900 |

**两个指标在 −10 和 −5 上都严格单调**,且方向一致:

> **解码期语言先验越强 → 泄漏越少、目标语音保留越多。**

H-LM 原本预测泄漏随先验强度**上升**。三级阶梯给出的是干净的**下降**。在 461 条的小集合上同样成立(0.593 / 0.402 / 0.240),只有 −5 dB 处 Qwen3 略高于 Whisper(0.135 vs 0.079)是唯一的非单调点,在 50 首的大集合上消失。

## 决定性证据:能转歌词 ≠ 会漏歌词

这是本次最强的一条,它**直接拆掉了"歌曲训练"这个混淆变量**。

纯歌声(无语音)输入时各模型能转出多少词:

| 模型 | 平均词数 | 完全转不出(<2 词) |
|---|---|---|
| whisper_ctc_offline | 12.8 | 6/50 |
| Whisper large-v3 | 9.4 | 9/50 |
| **Qwen3-ASR 1.7B** | **40.6** | **0/50** |

**Qwen3-ASR 的歌词转写能力是 Whisper 的 4 倍以上(40.6 vs 9.4 词),50 首无一失手——但它在混合条件下的泄漏率反而最低(0.244 vs 0.378)。**

也就是说:

- 它**最会**转歌词(被显式训练过,§6.6 二)
- 它**最不**在说话人在场时转歌词

**"具备转写歌词的能力"与"在混合条件下泄漏歌词"是两件可以分离的事。** 这正是 §6.1 引入 Granite 想要解耦的那个混淆——**而这份数据已经在没有 Granite 的情况下把它解开了**:如果歌曲训练是泄漏的驱动因素,song-trained 的 Qwen3 应该泄漏最多,实际它最少。

**对计划的直接影响:Granite 从"不可砍"降级为"锦上添花"。** 它仍能提供一个更严格的 2×2,但论文的核心论证已不依赖它。考虑到 §6.3 为它引入的整条英文臂约束和 Granite-8b 装不下 GPU 的问题,**这是排期上的重大解压**。

## 曲目效应贯穿整个阶梯

SNR −10 处逐曲目泄漏率的两两相关(n=50):

| | r |
|---|---|
| CTC vs Whisper | +0.760 |
| CTC vs Qwen3 | +0.673 |
| Whisper vs Qwen3 | +0.715 |

三个架构完全不同的模型,**漏在同一批歌上**。再次印证 pilot 03:**"哪些歌危险"由输入决定,架构只决定"漏多少"。**

## 语言翻车是 CTC 独有的

非英文输出占比:

| 模型 | −10 | −5 | 0 |
|---|---|---|---|
| whisper_ctc_offline | 18/250 | 11/250 | **38/250** |
| Whisper large-v3 | 0 | 0 | 0 |
| Qwen3-ASR | 0 | 0 | 0 |

两个带解码器的模型**一次都没翻**。CTC 在 0 dB(几乎无泄漏)反而翻得最多(15%)。
这坐实了 pilot 02 的推测:**问题出在"从第 1 帧 log-prob 读语种"这个单点判定**,与泄漏正交,是该实现的独立缺陷。**对生产有价值,但不该写进这篇论文的主线。**

## H-LM 应该改写成什么

原假设("显式 LLM 先验加剧歧义")已被三级阶梯反向证伪。建议改为:

> **H-LM′:解码期语言先验充当源选择的稳定器。先验越强,模型越倾向于锁定单一源并抑制竞争源,泄漏随之单调下降。**

机制解释与 H1 完全一致,且现在有两条独立支撑:

1. **自回归承诺**:解码器沿自身已生成上文继续,把选择锁住;CTC 逐帧独立,跟着瞬时能量摇摆。
2. **能力/倾向分离**:Qwen3 最会转歌词却最不漏,说明抑制是主动的选择行为,不是能力不足。

论文的主张从"架构趋势会放大问题"变成 **"我们量化了解码期先验对源选择的稳定作用,并给出它失效的条件(SNR ≤ −5 dB、竞争源可词汇化)"**。这比原来的版本机制更清楚,而且**所有结论都指向可操作的缓解方向**。

## 局限

1. **三级阶梯不是受控对照。** 三个模型的训练数据、编码器、规模全都不同。单调性是**关联**,不是"先验强度导致泄漏下降"的因果证明。Granite(显式先验、无歌曲训练)仍是最合适的补充对照,只是不再是必需品。
2. Qwen3 的词级时间戳还没用起来——**泄漏发生在片段哪一刻**尚未分析。
3. 仍是英文臂 + MUSDB(无歌词真值);中文臂待 MIR-1K 审批。
4. 泄漏指标依赖模型自身的纯歌声转写构造歌词参考;Qwen3 转得最多,会**抬高**它自己被判泄漏的上限——**而它仍然最低**,所以这个偏差只会让结论更保守。
