# Pilot 05 — Fig 3 第一次尝试:两个设计都不成立(记录失败与修法)

日期 2026-08-11 · `work/{probe_feats.npz, logit_lens*.json}`

目标是把 pilot 04 的**相关性**升级为**机制**:在 Whisper 单个模型内部定位歌词信息消失的位置,
从而绕开三模型对照的训练数据混淆。**两条路都没走通,原因值得记下来。**

## 尝试 A:线性探针(逐层)——探针太容易,天花板效应

设置:600 个切片(50 曲目 × 3 语音 × {C2_vocals, C1_rhythm} × {−10, −5}),
取 Whisper 编码器 33 个位置 + 解码器 33 个位置的**时间平均池化**表示,训练线性探针。

结果(编码器前 20 层):

```
enc L05  singing=1.000  songC2=1.000  songC1=1.000
enc L09  singing=1.000  songC2=1.000  songC1=1.000
enc L20  singing=0.981  songC2=1.000  songC1=0.680
```

**"是否有歌声"和"是哪首歌"从第 5 层起就是 100%。** 探针没有区分力。

**根因**:每首曲目**永远贡献同一段 10 秒音频**,所以任何与曲目相关的标签都可以靠记忆那段波形解出来,
和"是否编码了歌词的词汇内容"无关。这个设计从一开始就问错了问题。

**唯一有信息量的一条**:`songC1`(纯器乐)在深层下降到 0.68,而 `songC2`(人声)保持 1.000 ——
**编码器在深层丢弃器乐身份、却完整保留人声内容**。这与 H1 一致,但不足以支撑 Fig 3。

**修法**:改成**留出曲目**的**歌词词汇存在性**探针 —— 共享词表(出现在 ≥5 首歌歌词里的词),
多标签预测"这些词此刻是否被唱出",训练/测试**按曲目划分**。这样探针必须学会通用的
"这个词正在被演唱"映射,无法靠记忆某段波形取巧。同时应放弃全局平均池化,改用帧级或分段池化。

## 尝试 B:logit lens —— 中间层根本不在输出空间,比值是噪声

设置:57 个高泄漏切片(SNR −10),把每个解码器层的隐状态过 `layer_norm` + `proj_out`,
测"歌词专属 token"与"语音专属 token"的概率(**已按集合大小归一化**,修掉了第一版的偏置)。

```
layer   p_lyric   p_speech   ratio
  emb   0.01423   0.00267     5.321   <- 伪影(嵌入过输出头近似恒等)
  L06   0.00002   0.00002     1.230
  L20   0.00001   0.00002     0.732
  L25   0.00015   0.00013     1.209
  L28   0.00011   0.00003     3.344
  L31   0.00025   0.00006     4.019   <- 歌词偏好峰值
  L32   0.00089   0.00048     1.856   <- 最后一层砍半
```

表面上像个故事:**歌词偏好在 L25–L31 一路升到 4.0,最后一层被砍到 1.86**。

**但不能用**,三个理由:

1. **L01–L24 的概率量级是 1e-5**,两个集合都接近零,比值完全是噪声。logit lens 依赖
   "该层表示已在输出空间",Whisper 解码器中间层并不满足,过 `ln_f` 只是强行投影。
2. **对所有位置取平均**,包含特殊 token 与时间戳位置,信号被稀释。
3. 即使 L25–L32 的趋势为真,它只覆盖最后 1/4 的层,**无法回答"歌词在哪里消失"**——
   因为按 1 和 2,前面的层压根没测出来。

**修法**:
- 只在**模型实际吐出内容词的位置**上测,不要全位置平均;
- 用 **tuned lens**(为每层学一个到输出空间的仿射映射)替代直接过 `ln_f`,或者干脆放弃 lens;
- **更稳妥的替代:activation patching(原计划 Fig 4)。** 取一对同 SNR、同曲目的切片
  (一条泄漏、一条不泄漏),把某层残差流激活对调,看输出是否翻转。这是**因果**证据,
  不依赖"中间层是否在输出空间"这个前提,而且正是 *Beyond Transcription* 用过的方法。

## 尝试 C:激活 patching(编码器整层)—— 也不成立,且原因最简单

设置:同一条语音、同一首歌,只改混音比。donor = SNR +10(不泄漏),receiver = SNR −10(泄漏 0.914)。
逐层把 receiver 的第 L 层输出替换成 donor 的,再解码。

结果(6 对配对,32 层):

```
baseline mean leak 0.914
  L00 0.000    L08 0.000    L16 0.000    L24 0.000
  L01 0.000    L09 0.000    L17 0.000    L25 0.000
  ...          ...          ...          L31 0.000
```

**每一层都把泄漏打到 0.000,包括第 0 层。** 没有任何定位信息。

**根因(很基础,我一开始就该想到)**:编码器是纯前馈堆栈。把第 L 层的**整层输出**换成 donor 的之后,
第 L+1…31 层就成了 donor 表示的确定性函数,最终编码器输出 ≈ donor 的输出。
**"在任意层 patch"等价于"直接跑 donor"**,所以处处归零是必然的,与歌词信息存放在哪里无关。

**修法**:patching 要有定位能力,被替换的东西必须只是**残差流的一路贡献**,其余路径仍带 receiver 的信息:

- **换成 patch 子层输出**(attention 输出或 MLP 输出),而不是整层输出;残差流仍累加 receiver 的其余贡献。
- **或按时间窗 patch**:在第 L 层只替换部分帧(编码器 1500 帧),其余帧仍是 receiver 的。
  这样能同时给出**深度**和**时间**上的定位,而后者正是 pilot 04 拿到词级时间戳后最想要的维度。

## 结论与下一步

**三次尝试都失败,而且是同一类错误**:我设计操作时没有先问"这个操作到底控制/改变了什么"。

- A:标签与音频一一对应 → 探针只需记忆,不需泛化。
- B:把中间层强行过 `ln_f` → 假设了"中间层已在输出空间",而它不是。
- C:替换整层输出 → 下游全部变成 donor 的确定性函数,等价于直接跑 donor。

三次都不是"模型没有这个信息",而是**测量工具问不出这个问题**。这一点要记住:
机制类实验里,先证明操作有区分力(比如构造一个已知答案的 sanity check),再拿它去测未知。

优先级调整建议:

1. **子层级 / 时间窗 patching**(修法见尝试 C)。这是唯一还没试、且原理上能定位的路线,
   并且能同时给出时间维度,与 Qwen3 的词级时间戳互相印证。
   **上手前先做 sanity check**:patch 一个已知无关的层/时间窗,确认泄漏**不**归零。
2. 留出曲目的**歌词词汇探针**作为补充(修法见尝试 A),按 Cascade Equivalence 的
   CTC 可解码性范式做,而不是池化后的分类。
3. 若两者都不成,退回**行为学证据**:pilot 04 的能力/倾向分离(Qwen3 最会转歌词却最少泄漏)
   本身已经是很强的机制线索,配合阶梯单调性可以成篇,只是机制定位会弱一档。

**本次未产出可用图表,但排除了三条死路,并明确了 patching 必须做在子层/时间窗粒度上。**
